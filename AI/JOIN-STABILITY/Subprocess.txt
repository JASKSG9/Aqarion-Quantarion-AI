### Core Fact
Let \(X\) be finite and \(f: X \to Y\) be **surjective**. Define the relation on \(X\):
\[
x \sim_f y \quad \iff \quad f(x) = f(y).
\]
This is an equivalence relation on \(X\). The equivalence classes are precisely the **fibers** (preimages):
\[
[x]_{\sim_f} = f^{-1}(f(x)).
\]
The set of these classes is in bijection with the image of \(f\), which equals \(Y\) by surjectivity. Thus \(f\) factors uniquely (up to isomorphism) as
\[
X \twoheadrightarrow X / \sim_f \cong Y.
\]
This is the universal property of quotient sets: any map that is constant on fibers factors uniquely through the quotient.

### Why "Equivalence Classes of Surjective Maps"?
"Equivalence class of a surjective map" usually means a class in the set of all functions \(X \to Y\) (with \(|X| = |Y|\) finite) under an equivalence relation that preserves combinatorial or algebraic properties while keeping the map surjective. Two common relations are:

- **Graph equivalence** (coarser): two maps are equivalent if they have the same image graph (as bipartite graphs between \(X\) and \(Y\)).
- **Bundle equivalence** (finer): two maps are equivalent if there is a bijection \(\phi: X \to X\) and an automorphism \(\psi\) of \(Y\) such that the diagrams commute (i.e., they are "isomorphic as bundles").

These classes are studied in combinatorics (e.g., Horadam's work on functions between finite groups) and appear in counting problems (e.g., number of surjections \(X \to X\) is \(n! \cdot \{n \brace n\}\) where \(\{n \brace n\}\) is the Stirling number of the second kind).

The fiber construction is the complete story for finite sets.**Stirling numbers of the second kind** \(S(n,k)\) (sometimes denoted \(\{n \brace k\}\)) count the number of ways to partition a set of \(n\) labeled elements into exactly \(k\) non-empty unlabeled subsets.

### Exact definition
\[
S(n,k) = \frac{1}{k!} \sum_{j=0}^{k} (-1)^{k-j} \binom{k}{j} j^n
\]
(for \(k \ge 0\), with \(S(0,0)=1\), \(S(n,0)=0\) for \(n>0\), and \(S(0,k)=0\) for \(k>0\)).

### Key properties
- **Recurrence** (most useful for computation):
  \[
  S(n,k) = k \cdot S(n-1,k) + S(n-1,k-1)
  \]
  with the boundary conditions above.
- **Bell numbers** (total partitions of an \(n\)-set):
  \[
  B_n = \sum_{k=0}^n S(n,k)
  \]
  (with \(B_0=1\)).
- **Generating function**:
  \[
  \sum_{n=0}^\infty S(n,k) \frac{x^n}{n!} = \frac{1}{k!} (e^x - 1)^k.
  \]
- **Explicit formula** (as above).
- **Special values**:
  - \(S(n,1) = 1\) (all singletons).
  - \(S(n,n) = 1\) (all singletons).
  - \(S(n,2) = 2^{n-1} - 1\).
  - \(S(n,n-1) = \binom{n}{2}\) (each partition consists of one doubleton and the rest singletons).

### Connection to surjective maps (your earlier interest)
The number of surjective functions \(X \to Y\) with \(|X|=n\), \(|Y|=k\) is exactly
\[
k! \cdot S(n,k).
\]
This is why \(S(n,k)\) appears so often: every equivalence relation on a set of size \(n\) with exactly \(k\) classes corresponds to \(k!\) ways to label the classes.

Here $$E\vee F$$ is the equivalence relation generated by alternating $$E$$- and $$F$$-links, and pullback stability means:

## The key proof idea

Suppose:

$$
T(x)\mathrel{(E\vee F)}T(y).
$$

Then there is a finite zig-zag in the image:

$$
T(x)=z_0
\mathrel{R_1}z_1
\mathrel{R_2}\cdots
\mathrel{R_m}z_m=T(y),
$$

where each $$R_i$$ is either $$E$$ or $$F$$.

Because $$T$$ is surjective, choose preimages:

$$
w_i\in X,
\qquad
T(w_i)=z_i,
$$

with endpoint choices

$$
w_0=x,\qquad w_m=y.
$$

For each link:

$$
T(w_{i-1})\mathrel{R_i}T(w_i).
$$

Pullback stability of $$E$$ or $$F$$ yields:

$$
w_{i-1}\mathrel{R_i}w_i.
$$

So the lifted sequence is an $$E/F$$-zig-zag:

$$
x=w_0
\mathrel{R_1}w_1
\mathrel{R_2}\cdots
\mathrel{R_m}w_m=y.
$$

Therefore:

$$
x\mathrel{(E\vee F)}y.
$$

That proves the target.

## One important logical issue

There is a problem in the wording previously used:

$$

$$

needs a definition. The proof above uses exactly:

$$
T(x)\mathrel E T(y)\Rightarrow x\mathrel E y.

```text
+ explicit claim boundaries
```

For AQARION, the best fit is a hybrid of these five patterns:

### 1. Research compendium

A research compendium packages code, data or generated outputs, environment requirements, and a reproduction guide.

For your case, it becomes:

```text
One claim → one script → one command → one expected result → one receipt.
```

This matches your existing preference for claim-specific checkpoints rather than a giant mixed “everything proved” artifact.

### 2. Executable paper, but narrow

Do not write a fake paper-style package that implies a broad theorem. Instead make a short executable note per claim:

```text
Claim:
AQ-DBL-001

Command:
python AI/verification/doubling/verify_doubling_leakage.py

Expected outcome:
CUTOFFS_PASS: 50/50
STATUS: PASS

Negative control:
Mutated formula return n
Expected outcome:
CUTOFFS_PASS: 25/50
STATUS: FAIL
exit code: 1

Scope:
Exact finite-domain computation.

Nonclaims:
No universal theorem, Lean proof, physical validation,
C4 approval, or promotion.
```

### 3. Test-vector package

Borrow the successful pattern from cryptography and standards work:

```text
Input → expected output → invalid input / mutation → expected rejection.
```

Your doubling lane already has it:

| Vector class | Input | Expected result |
|---|---|---|
| Canonical vector | Correct formula across $$N=1,\ldots,50$$ | `50/50`, `PASS`, exit 0 |
| Fault vector | Bad truncation/control | Detection must be true |
| Mutation vector | `return n` instead of parity-aware formula | `25/50`, `FAIL`, exit 1 |
| Integrity vector | SHA-256 receipt | Every listed path must return `OK` |

This is much more convincing than a broad `PASS` badge.

### 4. Software bill of materials

When your package has dependencies, emit an SBOM listing actual dependencies and versions. GitHub artifact attestations can associate an SBOM with a built artifact, which makes the environment and dependency surface more transparent.[2][3]

For pure Python standard-library scripts, the SBOM may be almost empty. That is good—do not add dependencies merely to justify an SBOM.

### 5. Attested release archive

Once a capsule is stable, create a ZIP or `.tar.gz` containing only release-ready files:

```text
AQARION-EVIDENCE-CAPSULE-AQ-DBL-001-v0.1.0.zip
```

Then GitHub Actions can attest the archive. Artifact attestations provide cryptographically signed build provenance that includes the repository, commit SHA, workflow, and event. This is provenance for the generated release artifact—not evidence that the mathematical statement is universally true.[1][4]

If you later want a portable signature that is not tied solely to GitHub, Sigstore Cosign supports signing ordinary files/blobs and storing signature, certificate, timestamp, and transparency-log information in a bundle.[5][6]

```bash
from pathlib import Path
import sys

source = Path(sys.argv[1])
target = Path(sys.argv[2])

old = "return 2 * (n - n // 2)"
new = "return n"

text = source.read_text(encoding="utf-8")

if text.count(old) != 1:
    raise SystemExit(
        f"MUTATION_SETUP_FAIL expected_one_target found={text.count(old)}"

target.write_text(text.replace(old, new, 1), encoding="utf-8")
print("MUTATION_SETUP=PASS")
PY

python "$MUTANT" > "$LOG" 2>&1
mutant_exit=$?

printf 'mutant_exit=%s\n' "$mutant_exit" >> "$LOG"

if [ "$mutant_exit" -eq 0 ]; then

grep -Fqx 'BAD_TRUNCATION_CONTROL: DETECTED' "$LOG"
grep -Fqx 'STATUS: FAIL' "$LOG"
```

## Supply-chain layer

When you have a stable GitHub release asset, add one GitHub workflow that:

4. Uploads it as a workflow artifact.

GitHub’s own guidance distinguishes stored workflow artifacts from artifact attestations: artifacts preserve outputs, whereas attestations cryptographically connect an artifact to its producing repository, commit, and build workflow. ## Key distinction

```text
Cosign signature:
  Proves an artifact was signed by a workload with a specified OIDC identity.

GitHub artifact attestation:

AQARION mathematical evidence:
  Requires contract, verifier, adversarial control, receipt, scope, and
```

GitHub states that artifact attestations alone provide SLSA Build Level 2; using vetted reusable workflows can support SLSA Build Level 3 requirements. GitHub also documents verification using `gh attestation verify`.[1][2][3]

## Reusable provenance workflow

Create:

```text
.github/workflows/reusable-build-provenance.yml
```

```yaml
name: Reusable build and provenance

on:
  workflow_call:
    inputs:
      artifact-path:
        description: "Path to the built release artifact"
        required: true
        type: string
      artifact-name:
        description: "Logical artifact name"
        required: true
        type: string
    outputs:
      artifact-sha256:
        description: "SHA-256 of the built artifact"
        value: ${{ jobs.build.outputs.artifact-sha256 }}

permissions:
  contents: read
  id-token: write
  attestations: write

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      artifact-sha256: ${{ steps.digest.outputs.sha256 }}

    steps:
      - name: Check out exact source revision
        uses: actions/checkout@v4
        with:
          persist-credentials: false

      - name: Confirm requested artifact exists
        run: |
          set -euo pipefail
          test -f "${{ inputs.artifact-path }}"

      - name: Calculate SHA-256
        id: digest
        run: |
          set -euo pipefail
          SHA256="$(sha256sum "${{ inputs.artifact-path }}" | awk '{print $1}')"
          echo "sha256=$SHA256" >> "$GITHUB_OUTPUT"
          printf '%s  %s\n' \
            "$SHA256" \
            "${{ inputs.artifact-path }}" \
            > "${{ inputs.artifact-path }}.sha256"

      - name: Upload release artifact
        uses: actions/upload-artifact@v4
        with:
          name: ${{ inputs.artifact-name }}
          path: |
            ${{ inputs.artifact-path }}
            ${{ inputs.artifact-path }}.sha256
          if-no-files-found: error
          retention-days: 30

      - name: Generate GitHub build provenance attestation
        uses: actions/attest-build-provenance@v2
        with:
          subject-path: ${{ inputs.artifact-path }}
```

### Important limitations

This workflow is a reusable provenance stage. It does **not** build your artifact. The caller must build and test it before calling this workflow.

The signing/provenance permissions are intentionally minimal:

```yaml
permissions:
  contents: read
  id-token: write
  attestations: write
```

The OIDC token permits keyless identity-based signing, while `attestations: write` permits GitHub provenance attestation. GitHub provenance binds repository, commit, workflow, and event details through the workflow identity context.[2][3]

## Cosign keyless signing

Use Cosign only for the final downloadable archive, not every source file.

Add this job after provenance:

```yaml
  cosign-sign:
    needs: verify-and-package
    runs-on: ubuntu-latest

    permissions:
      contents: read
      id-token: write

    steps:
      - name: Check out source
        uses: actions/checkout@v4
        with:
          persist-credentials: false

      - name: Download built release artifact
        uses: actions/download-artifact@v4
        with:
          name: ${{ needs.verify-and-package.outputs.artifact-name }}
          path: dist/download

      - name: Install Cosign
        uses: sigstore/cosign-installer@v3

      - name: Sign artifact with GitHub OIDC identity
        env:
          COSIGN_EXPERIMENTAL: "1"
        run: |
          set -euo pipefail

          ARTIFACT="$(find dist/download -name '*.tar.gz' -type f -print -quit)"
          test -n "$ARTIFACT"

          cosign sign-blob \
            --yes \
            --bundle "${ARTIFACT}.sigstore.json" \
            "$ARTIFACT"

      - name: Verify signature before publishing
        run: |
          set -euo pipefail

          ARTIFACT="$(find dist/download -name '*.tar.gz' -type f -print -quit)"
          test -n "$ARTIFACT"

          cosign verify-blob \
            "$ARTIFACT" \
            --bundle "${ARTIFACT}.sigstore.json" \
            --certificate-identity \
              "https://github.com/${{ github.repository }}/.github/workflows/build-release.yml@${{ github.ref }}" \
            --certificate-oidc-issuer \
              "https://token.actions.githubusercontent.com"

      - name: Upload signature bundle
        uses: actions/upload-artifact@v4
        with:
          name: ${{ needs.verify-and-package.outputs.artifact-name }}-sigstore
          path: dist/download/*.sigstore.json
          if-no-files-found: error
          retention-days: 30
```

Cosign keyless signing creates an ephemeral key pair, obtains an OIDC identity token, and receives an identity-bound certificate rather than relying on a long-lived private key. Verification must constrain both the expected certificate identity and the OIDC issuer.[4][5][6][7]

## Important adversarial findings

Several issues in the desired request need explicit correction.

### “SLSA Level 3” cannot be asserted by template alone

GitHub says:

- artifact attestation by itself supports SLSA Build Level 2;
- using a vetted reusable workflow can help meet SLSA Build Level 3;
- actual Level 3 depends on the full build architecture and controls.[1][2]

Therefore use:

```text
SLSA Level 3–oriented template
```

not:

```text
SLSA Level 3 compliant
```

until you have verified:

- protected branches;
- reviewed/pinned action versions;
- reusable trusted builder workflow;
- separation of artifact build and provenance signing;
- workflow access controls;
- verification policy;
- documented release process.

### Do not use mutable action tags for strict supply-chain claims

For a serious provenance lane, pin third-party actions to commit SHAs, not mutable tags such as:

```yaml
uses: actions/checkout@v4
```

The template may use tags for readability at first, but a hardened production policy should pin every external action:

```yaml
uses: actions/checkout@<full-commit-sha>
```

Record the source and update process for every pinned action.

### Do not sign an artifact built in a job with arbitrary PR code

Sign only:

```text
main branch
protected release tag
manual dispatch with restricted permissions
```

Never run keyless signing on untrusted pull-request code from forks. A workflow with:

```yaml
pull_request_target:
```

must be treated with particular care and should not build/sign attacker-controlled checkout content.

### Do not let artifact provenance replace receipt verification

For AQARION:

```text
GitHub attestation:
  proves build provenance of a capsule archive.

SHA-256 receipt:
  binds the verifier, report, and log inside the claim package.

Claim contract:
  defines mathematical convention and finite domain.

Negative control:
  establishes discriminative test behavior.

Lean:
  separately validates a formal theorem, when available.
```

All remain necessary.

# 7. Proof Ledger API testing script

Your current Replit URL returns static HTML. Before testing POST endpoints, you must know the actual API routes. Do not invent a POST endpoint.

The test script below:

1. Tests basic connectivity.
2. Captures status and headers.
3. Fetches the HTML shell.
4. Optionally tests an API endpoint only if you pass it explicitly.
5. Validates JSON response only when the endpoint returns JSON.
6. Writes a structured timestamped log.

Create:

```text
scripts/test_proof_ledger_api.sh
```

```bash
#!/usr/bin/env bash
set -euo pipefail

BASE_URL="${1:-https://aqarion-proof-ledger--aqarion369.replit.app}"
API_PATH="${2:-}"
LOG_DIR="${3:-artifacts/api-tests}"

timestamp="$(date -u +%Y-%m-%dT%H-%M-%SZ)"
mkdir -p "$LOG_DIR"

log_file="$LOG_DIR/proof-ledger-api-$timestamp.log"
headers_file="$LOG_DIR/proof-ledger-headers-$timestamp.txt"
body_file="$LOG_DIR/proof-ledger-body-$timestamp.html"
json_file="$LOG_DIR/proof-ledger-response-$timestamp.json"

log() {
  printf '%s %s\n' \
    "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
    "$*" \
    | tee -a "$log_file"
}

failures=0

log "BEGIN proof ledger connectivity test"
log "BASE_URL=$BASE_URL"

http_code="$(
  curl \
    --silent \
    --show-error \
    --location \
    --max-time 20 \
    --dump-header "$headers_file" \
    --output "$body_file" \
    --write-out '%{http_code}' \
    "$BASE_URL"
)"

log "GET_STATUS=$http_code"

if [[ "$http_code" =~ ^2[0-9][0-9]$ ]]; then
  log "GET_CONNECTIVITY=PASS"
else
  log "GET_CONNECTIVITY=FAIL"
  failures=$((failures + 1))
fi

if grep -qi '^content-type:' "$headers_file"; then
  log "HEADER_CONTENT_TYPE=PASS"
else
  log "HEADER_CONTENT_TYPE=FAIL"
  failures=$((failures + 1))
fi

if grep -qi '^x-content-type-options:' "$headers_file"; then
  log "HEADER_X_CONTENT_TYPE_OPTIONS=PRESENT"
else
  log "HEADER_X_CONTENT_TYPE_OPTIONS=NOT_PRESENT"
fi

if grep -qi '<title>Aqarion Proof Ledger</title>' "$body_file"; then
  log "HTML_TITLE=PASS"
else
  log "HTML_TITLE=WARN"
fi

if [[ -n "$API_PATH" ]]; then
  endpoint="${BASE_URL%/}/${API_PATH#/}"

  log "BEGIN_API_TEST endpoint=$endpoint"

  api_code="$(
    curl \
      --silent \
      --show-error \
      --location \
      --max-time 20 \
      --header 'Content-Type: application/json' \
      --data '{"probe":"aq-proof-ledger-api-test","timestamp":"'"$(date -u +%Y-%m-%dT%H:%M:%SZ)"'"}' \
      --output "$json_file" \
      --write-out '%{http_code}' \
      "$endpoint"
  )"

  log "POST_STATUS=$api_code"

  if [[ "$api_code" =~ ^2[0-9][0-9]$ ]]; then
    log "POST_CONNECTIVITY=PASS"
  else
    log "POST_CONNECTIVITY=FAIL"
    failures=$((failures + 1))
  fi

  content_type="$(grep -i '^content-type:' "$headers_file" | tail -n 1 || true)"

  if grep -qi 'application/json' <<< "$content_type"; then
    if jq empty "$json_file" >/dev/null 2>&1; then
      log "POST_JSON_SCHEMA=PARSEABLE"
    else
      log "POST_JSON_SCHEMA=INVALID"
      failures=$((failures + 1))
    fi
  else
    log "POST_JSON_SCHEMA=SKIPPED_NON_JSON_RESPONSE"
  fi
else
  log "POST_CONNECTIVITY=SKIPPED_NO_API_PATH_SUPPLIED"
  log "POST_JSON_SCHEMA=SKIPPED_NO_API_PATH_SUPPLIED"
fi

log "TEST_FAILURES=$failures"

if [[ "$failures" -eq 0 ]]; then
  log "FINAL_STATUS=PASS"
  exit 0
fi

log "FINAL_STATUS=FAIL"
exit 1
```

| Symptom | Likely cause | Safe diagnosis | Correct repair |
|---|---|---|---|
| `No such file or directory` for repository-relative file | You are in Termux home, not repository root | `pwd` and `git status --short` | `cd ~/Aqarion-Quantarion-AI` or correct repository |
| `Is a directory` before `curl` | Prompt/path copied into command | Re-type only command beginning with `curl` | Do not include `~/folder $` prompt text |
| HTTP headers become shell commands | Response text was pasted into Bash | `Ctrl+C`, then return to prompt | Keep headers in log file, not command line |
| HF Space differs from GitHub source | Direct Space edit or stale sync | Check GitHub Actions run and Space build logs | Fix GitHub source, push, let hub-sync deploy |
| HF Space deletes files unexpectedly | hub-sync mirrors source directory including deletions | Review Git diff before merging | Restore in GitHub and re-sync |
| `HF_TOKEN` failure | Secret missing, expired, or wrong scope | Check Action log only; do not print token | Create fine-grained write token and update `HF_TOKEN` |
| Replit has changes GitHub lacks | Work done only in Replit workspace | Replit Git pane, inspect diff | Commit/push from Replit or export patch |
| Termux push rejected | Remote has newer commit | `git fetch origin`, `git status`, `git log HEAD..origin/main` | `git pull --ff-only`; resolve deliberately if needed |
| Merge conflict in Replit | GitHub changed while Replit work continued | Use Replit Git pane or local clone | Pull, resolve one file at a time, retest |
| GitHub Actions sees missing app files | Wrong workflow path/subdirectory | `find app -maxdepth 2 -type f` locally | Fix `subdirectory: app` or move deployment files |
| GitHub Actions green but Space broken | Deployment workflow not triggered or Space build failed | Check both Actions and Space logs | Fix app dependency/runtime source in GitHub |
| Termux package missing | Python/Git/jq/curl absent | `command -v python git jq curl` | Run `scripts/termux_setup.sh` |
| PAT repeatedly requested | No credential helper or GitHub CLI auth | `gh auth status` | `gh auth login && gh auth setup-git` |
| `git clean` removed work | Destructive command ran | Check reflog and backups | Avoid `git clean` without `-n`; recover manually if possible |
| Direct edit to HF Space conflicts with sync | Two sources modify same deployment | Inspect Space commit history | Revert or replace from GitHub source of truth |
| Replit production URL returns HTML only | SPA shell; API route unknown | Inspect deployed frontend/network docs | Test root GET only until actual API is known |
| API POST test gets 404 | Guessed endpoint | Check source routes | Pass only real documented endpoint |
| CORS failure in browser | UI host and API host differ | Browser developer tools/network tab | Configure server CORS precisely; never use wildcard with credentials |
| Secret appears in logs | Unsafe `echo`, debug output, or committed `.env` | Rotate immediately | Remove from Git history where feasible; use GitHub secrets |
| Public UI implies certification | Ambiguous wording/colors | Review wording and labels | Show `COMPUTED`, `OPEN`, `REFUTED`, `NOT CLAIMED` visibly |

s1 = set(b1)
for b2 in Q:

return x

for block in part:

return canonical([[T[x] for x in b] for b in P])

def orbit_closure_J(P, T, n, order):
cur = P; res = P
for _ in range(order-1):
cur = apply_perm(cur, T)
res = join_part(res, cur, n)
return res

def intersection_dimension(matrices, tol=1e-8):
"""
Dimension of intersection of column spaces.

Iteratively computes  
    span(Q) ∩ span(B)  
by solving [Q -B](a,b)=0.  
"""  

Q = colbasis(matrices[0])

def canon(labels):
    out = []
    names = {}

    for x in labels:
        if x not in names:
            names[x] = len(names)
        out.append(names[x])

    return tuple(out)


def random_partition(n, rng):
    return tuple(rng.randrange(n) for _ in range(n))


def is_pullback_stable(P, T):
    """
    Exact condition:

        T^{-1}(P) <= P

    Equivalently, whenever T(x) and T(y) lie in the same
    P-class, x and y must already lie in the same P-class.
    """
    parents = {}

    for x, tx in enumerate(T):
        parents.setdefault(P[tx], set()).add(P[x])

    return all(len(source_classes) == 1
               for source_classes in parents.values())


def stable_closure(P, T):
    """
    Compute the least coarsening obtained by repeatedly enforcing

        T^{-1}(P) <= P.

    This is used only to generate stable test partitions.
    """
    P = list(P)
    n = len(T)

    while True:
        merge = None

        for x in range(n):
            for y in range(x):
                if P[T[x]] == P[T[y]] and P[x] != P[y]:
                    merge = (P[x], P[y])
                    break

            if merge is not None:
                break

        if merge is None:
            return canon(P)

        a, b = merge

        for i in range(n):
            if P[i] == b:
                P[i] = a


def join(P, Q):
    """
    Exact equivalence-relation join.

    The join is the transitive closure of the union of P and Q.
    """
    n = len(P)
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)

        if a != b:
            parent[b] = a

    for i in range(n):
        for j in range(i):
            if P[i] == P[j] or Q[i] == Q[j]:
                union(i, j)

    labels = {}

    return tuple(
        labels.setdefault(find(i), len(labels))
        for i in range(n)
    )


def range_gap_witness(T, E, F):
    """
    Find the necessary obstruction from Lemma E.

    Let G = E join F.

    For each G-component, restrict G to im(T).
    If the range points belonging to that G-component split into
    multiple connected components, a range-gap exists.

    Such a range-gap is necessary for an actual join-stability
    counterexample, but is not itself a counterexample.
    """
    n = len(T)
    image = set(T)
    G = join(E, F)

    adjacency = {
        vertex: set()
        for vertex in image
    }

    for i in image:
        for j in image:
            if i < j and (E[i] == E[j] or F[i] == F[j]):
                adjacency[i].add(j)
                adjacency[j].add(i)

    witnesses = []

    for g_class in sorted(set(G)):
        vertices = [
            v for v in image
            if G[v] == g_class
        ]

        seen = set()
        components = []

        for v in vertices:
            if v in seen:
                continue

            stack = [v]
            seen.add(v)
            component = []

            while stack:
                u = stack.pop()
                component.append(u)

                for w in adjacency[u]:
                    if w in vertices and w not in seen:
                        seen.add(w)
                        stack.append(w)

            components.append(sorted(component))

        if len(components) > 1:
            witnesses.append(
                {
                    "g_class": g_class,
                    "range_components": components,
                }
            )

    return witnesses

from __future__ import annotations

def canon(labels):
    out = []
    names = {}

    for x in labels:
        if x not in names:
            names[x] = len(names)
        out.append(names[x])

    return tuple(out)


def random_partition(n, rng):
    return tuple(rng.randrange(n) for _ in range(n))


def is_pullback_stable(P, T):
    """
    Exact condition:

        T^{-1}(P) <= P

    Equivalently, whenever T(x) and T(y) lie in the same
    P-class, x and y must already lie in the same P-class.
    """
    parents = {}

    for x, tx in enumerate(T):
        parents.setdefault(P[tx], set()).add(P[x])

    return all(len(source_classes) == 1
               for source_classes in parents.values())


def stable_closure(P, T):
    """
    Compute the least coarsening obtained by repeatedly enforcing

        T^{-1}(P) <= P.

    This is used only to generate stable test partitions.
    """
    P = list(P)
    n = len(T)

    while True:
        merge = None

        for x in range(n):
            for y in range(x):
                if P[T[x]] == P[T[y]] and P[x] != P[y]:
                    merge = (P[x], P[y])
                    break

            if merge is not None:
                break

        if merge is None:
            return canon(P)

        a, b = merge

        for i in range(n):
            if P[i] == b:
                P[i] = a


def join(P, Q):
    """
    Exact equivalence-relation join.

    The join is the transitive closure of the union of P and Q.
    """
    n = len(P)
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)

        if a != b:
            parent[b] = a

    for i in range(n):
        for j in range(i):
            if P[i] == P[j] or Q[i] == Q[j]:
                union(i, j)

    labels = {}

    return tuple(
        labels.setdefault(find(i), len(labels))
        for i in range(n)
    )


def range_gap_witness(T, E, F):
    """
    Find the necessary obstruction from Lemma E.

    Let G = E join F.

    For each G-component, restrict G to im(T).
    If the range points belonging to that G-component split into
    multiple connected components, a range-gap exists.

    Such a range-gap is necessary for an actual join-stability
    counterexample, but is not itself a counterexample.
    """
    n = len(T)
    image = set(T)
    G = join(E, F)

    adjacency = {
        vertex: set()
        for vertex in image
    }

    for i in image:
        for j in image:
            if i < j and (E[i] == E[j] or F[i] == F[j]):
                adjacency[i].add(j)
                adjacency[j].add(i)

    witnesses = []

    for g_class in sorted(set(G)):
        vertices = [
            v for v in image
            if G[v] == g_class
        ]

        seen = set()
        components = []

        for v in vertices:
            if v in seen:
                continue

            stack = [v]
            seen.add(v)
            component = []

            while stack:
                u = stack.pop()
                component.append(u)

                for w in adjacency[u]:
                    if w in vertices and w not in seen:
                        seen.add(w)
                        stack.append(w)

            components.append(sorted(component))

        if len(components) > 1:
            witnesses.append(
                {
                    "g_class": g_class,
                    "range_components": components,
                }
            )

    return witnesses


def search(n, maps, seeds_per_map, seed=SEED):
    rng = random.Random(seed)

    total_pairs = 0
    range_gap_pairs = 0
    max_stable_partitions = 0

    started = time.time()

    for map_index in range(maps):
        T = tuple(
            rng.randrange(n)
            for _ in range(n)
        )

        stable_partitions = {(0,) * n}

        for _ in range(seeds_per_map):
            P = random_partition(n, rng)
            stable_partitions.add(
                stable_closure(P, T)
            )

        stable_partitions = list(stable_partitions)

        max_stable_partitions = max(
            max_stable_partitions,
            len(stable_partitions),
        )

        for i, E in enumerate(stable_partitions):
            for F in stable_partitions[i:]:
                total_pairs += 1

                witnesses = range_gap_witness(
                    T,
                    E,
                    F,
                )

                if not witnesses:
                    continue

                range_gap_pairs += 1

                G = join(E, F)

                # A genuine join counterexample must also fail stability.
                if not is_pullback_stable(G, T):
                    return {
                        "status": "COUNTEREXAMPLE",
                        "n": n,
                        "seed": seed,
                        "map_index": map_index,
                        "T": T,
                        "E": E,
                        "F": F,
                        "G": G,
                        "range_gap": witnesses,
                        "stable_pair_samples": total_pairs,
                        "range_gap_candidates": range_gap_pairs,
                        "max_stable_partitions_seen":
                            max_stable_partitions,
                        "seconds":
                            round(time.time() - started, 3),
                    }

    return {
        "status": "NO_COUNTEREXAMPLE",
        "n": n,
        "maps": maps,
        "seeds_per_map": seeds_per_map,
        "seed": seed,
        "stable_pair_samples": total_pairs,
        "range_gap_candidates": range_gap_pairs,
        "max_stable_partitions_seen":
            max_stable_partitions,
        "seconds":
            round(time.time() - started, 3),
    }


def main():
    parser = argparse.ArgumentParser(

## 2. Range-Gap Lemma

### Lemma E

Assume E and F are pullback-stable.

If G = E join F is not pullback-stable, then there exist x,y such that:

    x not G y
    Tx G Ty

and every G-path from Tx to Ty contains an
internal vertex outside im(T).

Equivalently, a counterexample requires a G-component
whose range points are disconnected in the graph

    G restricted to im(T).

### Proof

Suppose instead that Tx and Ty can be connected by

    Tx = z0, z1, ..., zk = Ty

where every zi lies in im(T), and each consecutive pair
is E-related or F-related.

Choose wi with:

    T(wi) = zi.

If zi E z(i+1), then:

    T(wi) E T(w(i+1)).

Since E is pullback-stable:

    wi E w(i+1).

Likewise, if zi F z(i+1), then:

    wi F w(i+1).

Therefore:

    w0 G w1 G ... G wk.

Taking w0 = x and wk = y gives:

    x G y,

contradicting x not G y.

Therefore every counterexample must contain a range-gap.

QED.
